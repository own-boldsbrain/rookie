# Domain Docs

How engineering skills consume this repository's domain documentation.

## Before exploring

- Read `CONTEXT.md` at the repository root when it exists.
- Read relevant architectural decisions under `docs/adr/` when they exist.
- Proceed silently when either source is absent.

## Layout

This repository uses a single-context layout: one root `CONTEXT.md` and system-wide ADRs under `docs/adr/`.

## Vocabulary

Use terms from `CONTEXT.md` in issue titles, proposals, hypotheses, and test names. If a required concept is absent, avoid inventing a synonym and note the gap for domain modeling.

## Architectural decisions

Surface any conflict with an existing ADR rather than silently overriding it.
